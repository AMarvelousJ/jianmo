# 煤堆与堆取料过程仿真规格

日期：2026-10-01。需求 Q1–Q28 已确认；用户授权规格设计及独立原型验证，验收入口已确认。本文为待审阅开发规格，不表示正式实现完成。

## Problem Statement

当前煤堆仅为静态演示网格，机器虽能运动，堆料/取料并不改变物料形状和数量。操作者不能验证机器与煤堆的空间作用、目标吨位、散落回收和自动作业过程。现有参数也不能保证首批堆料机与取料机处理同一可达煤堆。

## Solution

在独立物料模型中保存煤形和数量，以机器权威姿态推导卸料点与斗轮作用包络，产生可核对的局部堆积、取料及松落；Unity 展示同一煤形与实际煤流。先在北端 12# 区、ST01/RC01 验证手动闭环，再实现折返平顶堆料与分层回转取料，最后扩展全场。保留现场点云和实测几何入口，不宣称首版为实测现场复现。

## User Stories

1. 作为操作者，我希望选择空场或预置煤堆，以便分别验证堆料与取料。
2. 作为操作者，我希望煤堆随实际落点增长，以便判断机器运动与物料是否对应。
3. 作为操作者，我希望斗轮只在真实接触区域取煤，以便避免隔空扣除库存。
4. 作为操作者，我希望看到局部削减和坡面松落，以便观察取料后的堆形。
5. 作为操作者，我希望分别看到区内煤和散落煤，以便核对全部库存。
6. 作为操作者，我希望能够取回可达散落煤，以便模拟回收。
7. 作为操作者，我希望设置 t/h 请求流量，以便控制作业节奏。
8. 作为操作者，我希望看到受轮速、带速和接触限制的实际流量，以便知道设备为何达不到请求值。
9. 作为操作者，我希望单独试转轮带不改变煤量，以便继续运动调试。
10. 作为操作者，我希望设置目标吨位，以便按实际完成量结束作业。
11. 作为操作者，我希望看到不可达余煤及目标缺口，以便区分取尽可达区与完成目标。
12. 作为操作者，我希望能够暂停、恢复和终止，以便控制物料作业。
13. 作为操作者，我希望短暂无接触时零流量等待，以便移动设备寻找物料。
14. 作为操作者，我希望设备停止、急停和断线会暂停作业，以便保护触发后不自动续流。
15. 作为操作者，我希望手动命令可以接管自动作业，以便调整设备位置。
16. 作为操作者，我希望恢复自动时重新检查煤形并规划，以便不沿用过时路径。
17. 作为操作者，我希望同区堆取料互斥，以便避免两机同时改变同一区域。
18. 作为操作者，我希望暂停保留区占用、断线停稳后释放，以便保证短暂停顿与控制接管规则一致。
19. 作为操作者，我希望机器复位保留煤堆，以便调整姿态不破坏物料记录。
20. 作为操作者，我希望物料场景重置需要停机、控制权及确认，以便避免其他客户端清空库存。
21. 作为操作者，我希望重启恢复煤形与作业进度但保持停止，以便显式决定是否续作。
22. 作为操作者，我希望看到最近保存时间及存档故障，以便知道哪些进度已经保存。
23. 作为操作者，我希望自动折返堆料形成平顶堆，以便验证典型堆料工艺。
24. 作为操作者，我希望自动取料分层回转并按切片进车，以便验证典型取料工艺。
25. 作为维护者，我希望演示参数及可达性有版本和来源，以便后续替换为实测数据。
26. 作为观察客户端，我希望煤形和账本一致且不暴露控制凭据，以便安全查看作业。

## Implementation Decisions

### 权威状态与计算

- 沿用现有单进程后端、机器控制租约、单调墙钟超时、1× 时间及固定运动步长。物料仿真按累计仿真时间推进；不能依赖 Unity 帧数或由客户端增加物料。
- 增加物料区域、煤料参数、煤形、区域占用、物料账本、作业记录和快照版本。机器运动与作业记录分开，前阶段保护行为保留。
- 单位：长度 m、角度 deg、时间 s、体积 m³、质量 t、请求/实际流量 t/h；内部流量转换 t/s 后积分。密度采用 t/m³，首版固定，初始质量与所有增减均由体积换算。
- 地面高度与煤层厚度分别存储，每格煤层非负。首版不表示悬空或地下空洞。网格分辨率先比较 1、0.5、0.25 m，定案须兼顾几何误差与计算/通信性能。
- 松落在有限计算域内转移体积，支持横纵及斜向坡度限制。最终求解器须记录收敛阈值、迭代/时间预算及未收敛状态，不得为了平滑形状增减体积。
- 区内/散落分类由固定区域掩码决定，随物料移动重新统计，避免重复累计散落量。初始总库存 + 接收输入 - 输出 = 当前区内库存 + 当前散落库存；账本为实际接收与实际输出，非请求量。
- 无空间接收或硬堆高限制时拒绝未接收部分并显示原因，不把它计作输入。物料域外卸料拒绝生效；已在域内的松落不凭空流失到未建模区域。

### 几何标定与作用包络

- 首批候选北端 12# 区及 ST01/RC01。现有行程 X 不重叠；须以实际轨道边界为依据，提出版本化行程候选并通过 Unity 姿态验证。不得直接把后端参数调整视为现场限位。
- 保留初始摆位、角色、轨道和模型尺寸。需要修改尺寸时另行确认。取料包络来自当前轮体、桶齿几何，不能为了可达而放大。
- 堆料卸料点为臂架前端明确标记。后端使用同一标定正运动学推导点位，Unity 标记仅用于对照。煤流在重力方向与地面/煤面相交后按限定落料核分布，不把轮心当落点。
- 取料作用为斗轮包络随当前步运动形成的切削范围，并受煤面真实相交和可用库存约束。高度模型削减后执行保守松落，不用大圆形库存扣减替代实际轮体几何。
- 轮带速度能力采用可配置、单调且零速为零的演示曲线。实际流量为请求值、输送/轮斗能力、几何可取量或可接收量的最小约束；首版无需假装现场标定精度。
- 共同可达“作业区”不要求两机作用点完全相同；必须证明能堆形成目标煤形，并从中实际取回一部分。中心不可达余煤保留和报告。

### 作业与权限

- 每项作业包含身份、区域、机器、角色、manual/automatic 模式、可选目标吨位、实际完成吨位、状态、原因及规划版本。无目标的手动作业持续至操作者终止或保护暂停。
- 作业状态：running、paused、completed、terminated、incomplete、stopped（重启恢复）。无接触是 running 下的零流量等待原因，不自动报告整堆无煤。只有完成可达范围搜索或显式检查后才能判定物料不足。
- 目标达到时截断当前步增减到剩余量，允许明确的数值容差，完成后物料流量为零；不强制停止独立轮带试转。提前不可继续时标记 incomplete，保留缺口与余煤；不冒充 completed。
- 开始/恢复/暂停/终止沿用机器控制权、命令序号和幂等保护。区域占用在原子校验后授予，一次只能一台机器进行物料作业；暂停且连接有效仍保留占用，终止/完成/incomplete 后释放。
- 断线触发暂停并普通停机，停稳后释放区域及控制租约。新客户端必须显式获取机器控制及区域，才可恢复已有目标与剩余量，不自动继承控制令牌。
- 自动中手动三轴命令取消计划、暂停物料，再执行手动运动。恢复后重新规划；手动 jog 仍按已确认轴接管和加减速行为执行。
- 操作者发起驱动停止即暂停作业；不因停止后的减速期间仍有转速而自动继续物料。急停即时停止并锁定；解除急停只解除机器锁，不恢复作业。机器复位终止该机作业，煤形及账本不变。
- 自动作业采用折返平顶堆料；取料分层回转，当前切片后进车、逐层下降。规划只下达受运动内核约束的目标，控制推进同样要检查区域、租约、边界及库存。

### 对外协议及 Unity 表现

- 物料命令类别：start_job、pause_job、resume_job、terminate_job、reset_material；携带区域、模式、请求流量、可选目标及控制认证。具体路由沿用现有机器命令接口，区域操作可增加专用入口，但共享幂等与序号语义。
- 配置暴露区域范围、掩码、地面、网格、煤料参数、几何标定版本及 demo 来源。不得公开租约 token。
- 状态增加物料版本、账本、作业、区域占用、实际流量和原因、最近成功存档时间。保留服务实例和递增快照序号，煤形增量含 base_version/new_version；缺失增量、重连或实例变化必须重新获取完整煤形。
- 网格与账本属于同一逻辑版本，客户端不能将不同版本拼成库存。轮询账本不每帧携带全场大网格；完整快照、区域差量分离，实例和版本共同防止旧异步响应覆盖。
- Unity 为首批区域建立动态煤网格，散落煤同域显示；替换局部静态煤表面，保存备份及区域外几何，不重建港区。两份场景及生成器保持可重复绑定。
- UI 提供目标/请求流量、模式、开始/暂停/恢复/终止、物料场景初始化/重置、实际流量、输入/输出/区内/散落/总库存、未完成原因与保存状态。动作按控制权和区域占用启用，视觉煤流与实际流量一致。

### 存档与场景重置

- 每约 1 秒、暂停/终止/重置后，保存同一逻辑版本的煤形、密度/配置版本、初始库存、账本、作业进度及校验信息。临时文件写完并同步后原子替换，保留上一完整版本。
- 异常退出允许失去最近保存周期，不承诺每步持久化。保存失败明确显示并禁止静默声称已保存；损坏、版本不兼容时拒绝盲目载入，保留证据，验证备份或提示人工恢复。
- 恢复物料与目标进度，清空机器/区域控制凭据，所有作业记录转停止状态；机器按前阶段初始状态启动。显式恢复重新校验、占用、规划。
- 重置要求相关机器及作业停止、操作者持有相关控制权和二次确认；原子替换物料及账本，重建初始库存，清零本轮输入输出，结束旧作业，不复用旧增量版本。

## Testing Decisions

用户已确认以“公开命令 → 状态快照”为主要验收入口。沿用运动阶段可控时钟、API 参数校验及幂等行为测试，不用私有方法调用代替作业行为。Unity 补充实际姿态、作用点、煤形与权威状态核对。

1. 空场/预置初始化、流量单位换算、输入输出/散落分类、松落守恒与非负性。
2. 同等供料在三种网格的形状、库存及耗时比较；建议守恒绝对误差 ≤ max(1e-8 m³, 累计处理量×1e-9)，几何容差以网格精度为依据。容差为软件指标，不是现场精度。
3. 不接触零流量、部分接触限流、零轮/带速、供料边界/堆高拒绝、散落回收、不可达余煤保留。
4. 相同目标不同步长累计一致、最后一步不超目标、暂停和重启保留剩余量。
5. 无控制权/跨机/同区竞争拒绝、幂等与乱序、保护立即暂停、自动手动接管、暂停占用及断线停稳释放。
6. 快照写入中断、校验损坏、备份恢复、配置不兼容、重启无自动续流、旧服务/旧物料版本响应拒绝。
7. Unity 实际标定卸料点及轮体包络；左右代表机堆/取导致局部真实变化，姿态与后端正运动学误差有记录。
8. 自动折返堆形、分层切片进车、当前煤形重规划、终止/提前结束状态；人工保护操作补足运动阶段未闭环项。
9. 记录真实主机的计算、同步、网格更新耗时与画面表现，再决定物料更新频率和分辨率；数值脚本耗时不能当作 Unity FPS。

## Out of Scope

逐颗粒 DEM、地下空洞/悬空煤壁、压实密度变化、多煤种混煤、全输送线路库存、现场 PLC/设备控制、全场碰撞保护、无实测数据的现场精度声明。首批不同时完成全部 21 台物料过程；自动阶段在手动闭环通过后开展。

## Further Notes

三篇论文分别用于工艺、表面重建和几何计算参考；其现场尺寸、层数及测量精度不能直接充当本项目标定结果。已确认需求与资料阅读记录保留。

本地任务跟踪沿用已有 .scratch 方式。数值原型隔离于现役应用，正式开发须基于其验证边界重新实现，不直接把临时算法视为生产内核。规格状态为 ready-for-agent（内容可用于开发拆分），几何/性能相关步骤仍依赖原型验证，标签不表示已通过全部验证。

首轮原型结论：0.5 m 网格为候选；数值供入 160 m³、取出 20 m³后守恒误差约 3.41e-13 m³。两份 Unity 临时预览场景完成 12 组姿态核对；实测模型全转包络可接触候选 ST 堆形约 0.760621 m³，支持进一步开展局部闭环，但不证明全堆可达或瞬时切削能力。行程候选 ST01 上限 -395、RC01 下限 -425，未改动正式配置。原型报告明确了算法、存档及渲染尚未验证的边界。
