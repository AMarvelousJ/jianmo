# 区域占用与物料重置

## 作业区域

每个配置作业区同时只能被一个物料作业占用。开始与恢复在世界锁内检查占用，竞争返回 `ZONE_BUSY`，原因说明占用设备。`/api/state` 新增 `zone_occupancy`，键为区域名，空闲为 null，占用值含 `job_id` 和 `machine_id`，不含控制令牌。

运行及有效连接下的暂停保留区域；完成、终止、显式 incomplete 收尾、机器复位立即释放作业区域。复位终止作业但保留煤形与账本。驱动停止、普通停止和急停立即暂停物料；普通停止按加减速规则停机，急停立即停机并锁定。解除急停不恢复作业。

主动释放控制权或连接超时，立即暂停物料并普通停机；减速期间控制权为 releasing，区域仍占用。停稳后同时释放机器租约和区域，暂停记录及进度保留。新客户端获取机器控制权不会自动恢复；发送 `resume_job` 再次检查并申请区域，被其他机器占用则拒绝。仍沿用机器命令序号、幂等及控制权校验。

当前仅 ST01/RC01 手动作业。自动计划接管与按当前煤形重规划尚未实现，07 不勾选该验收项。

首批仅一个北端 12# 物料域，每个网格只接受一个作业区配置；域内煤堆及散落煤共同受此作业锁保护。禁止通过多个区域名把同一网格拆成可并行写入的区域。多域并行需后续建立独立物料作用范围，当前不支持。

## 物料场景初始化与重置

`reset_material` 作为现有机器命令发送，payload 包含 `mode`（empty/preset）、`confirm`（布尔值）及 `controls`（另一相关设备的控制凭据）。当前物料域关联 ST01 和 RC01，发起设备必须为其中一台；同一个客户端必须同时持有两台机器有效租约。

两个设备均须停稳，物料作业不得处于 running/paused；需先显式终止或收尾。首次初始化未建立场景时可不确认；已建立场景的重置即使库存为零也必须 `confirm=true`。条件全部成立后才替换煤形并重建初始库存、清零输入输出，物料版本递增。命令重复回放不重复重置，乱序或跨机令牌被拒绝。

例如由 ST01 发起时，沿用其控制凭据发送 `kind=reset_material`：

```json
{
  "mode": "preset",
  "confirm": true,
  "controls": [
    {"machine_id": "RC01", "token": "RC01的有效令牌", "generation": 2}
  ]
}
```

兼容路径 `POST /api/material/scene` 现在也走同一个认证命令，不接受原来仅 mode/confirm 的无认证写入。请求须含 `machine_id`、`client_id`、`token`、`generation`、`command_id`、`command_seq`，以及上述 mode/confirm/controls，成功返回该命令保存的物料快照。它与普通机器命令共享命令序号。缺字段返回 422，缺少/无效相关控制权返回 403，作业或运动/确认条件未满足返回 409。

`World.init_material` 只用于可信进程内启动与测试构造，不是 HTTP 或客户端操作入口。Unity 初始化/重置界面由 10 接入；跨重启存档由 08 完成。

验收入口：`tests/test_job_protection.py`、`tests/test_material_control.py`。包括并发同区竞争、暂停保留、停稳释放和接管、终结释放、保护联动、无认证写入拒绝、双设备权限、运动/作业守卫、确认、重置幂等与乱序、跨客户端和跨设备拒绝。
