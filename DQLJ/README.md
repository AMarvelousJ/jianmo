# 堆取料机仿真程序

第一阶段实现独立的机器运动仿真：21 台设备，左侧 7 台堆料角色、右侧 14 台取料角色；支持行走、回转、俯仰、斗轮、皮带及客户端控制租约。Unity 负责交互与表现，Python 保存权威状态。

## 启动

在本目录安装 `uv pip install --python ../.venv/Scripts/python.exe -e ".[test]"`，然后执行：

```powershell
.\scripts\start_backend.ps1
```

默认地址 `http://127.0.0.1:8001`，接口文档 `/docs`。仅监听本机，单进程单 worker。也可以使用 `python -m uvicorn yard_motion.api:app --host 127.0.0.1 --port 8001`。

## Unity 操作

打开现役 Demo 场景进入 Play Mode，点击屏幕中央的“堆场控制”。选择 ST/RC 设备、获取控制权后，输入三轴目标或按住正反向按钮。斗轮和皮带独立设置速度并启停。普通停止减速，急停立即停止并锁定，复位恢复初始姿态且不解除急停。

切换选机只停止原设备 jog；其他运动继续。退出、断线后租约超时触发减速停机，停稳后释放。重连不续跑。后端重启时机器恢复初始停止状态，物料与目标进度从有效存档恢复。

## 参数与边界

`config/machines.json` 为版本化演示配置，轨道与摆位来自两份场景核对；速度、加减速度、角度范围和 1 场景单位/米均为演示参数，不是现场测量。机械几何缩放 0.455 与行走映射独立。

`config/material.json` 与 `config/geometry.json` 属第二阶段（煤堆与堆取料过程）：物料网格、账本、煤料演示参数与作业区候选；几何标定（卸料点、斗轮包络）版本化，行程候选为未应用提案。ST01 手动堆料、RC01 手动取料及散落回收快照已实现（工单 01–05）；实际桶齿随本步姿态与轮相位扫掠取煤，八邻域松落保守转移体积并报告收敛预算。06 的目标控制、07 的手动区域互斥及 08 的存档恢复已实现；全工作区不可达余煤及 Unity 煤形显示尚未完成。

物料作业以 `/api/machines/{id}/commands` 发送 `start_job`（zone=`north-12`、mode=`manual`、requested_flow_t_per_h），轮带单独试转不改变煤量。取料需轮带均运行；不接触时零流量等待。停止、急停、控制权释放/超时会暂停物料，复位终止作业而保留煤堆。完整操作界面留到后续工单。

`start_job` 可选 `target_t`，按实际吨位完成并截断最后一步，完成后轮带仍可试转。`finish_job` 显式提前收尾，保存缺口与当前姿态接触报告。06 的重启进度保存已由 08 补齐，全工作区不可达余煤报告仍待实现，契约见 [作业目标与收尾](docs/物料作业目标与收尾.md)。

07 的手动范围已补区域互斥与保护：暂停保留占用，控制超时减速停稳后释放，恢复必须重新申请区域。物料初始化/重置统一走认证命令，要求同一客户端持有 ST01/RC01 控制权、停稳、结束作业和确认；重启恢复的 stopped 作业可在确认重置时终结。原无认证写入方式不再接受。07 的自动计划接管仍待第二批。见 [区域占用与物料重置](docs/区域占用与物料重置.md)。

默认服务在 `data/material-snapshot.json` 保存物料，每约 1 秒及暂停/终止/重置后保存，保留 `.bak`；可用 `DQLJ_SNAPSHOT_PATH` 改路径。重启恢复煤形、账本和目标进度，作业转 stopped，机器停止且清空控制权；显式恢复重新申请区域。`/api/state.persistence` 显示成功时间和故障。损坏档先保留证据并验证备份，无有效档时阻止物料写入。详见 [物料存档与恢复](docs/物料存档与恢复.md)。

`GET /api/material/grid` 按需读取煤厚、地面高程、分类掩码和同版本物料账本；数组按 `z_index * cells_x + x_index` 排列，采样位置为单元中心，坐标与高程单位为米。散落量是当前分类库存，取回后随库存减少。接口契约见 [物料网格快照](docs/物料网格快照.md)；Unity 接入由 09 票完成。

碰撞保护与真实设备控制仍不在范围内。机器运行姿态不存档；同步物料保存可能短暂延迟控制，端到端实时表现尚待 Unity 联通验收。
