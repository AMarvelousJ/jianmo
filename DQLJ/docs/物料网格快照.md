# 物料网格快照

`GET /api/material/grid` 返回一次完整快照，不推进仿真，不需要机器控制权。与运动轮询 `/api/state` 分开，客户端按需拉取。完整快照还包含同一锁内读取的 `jobs`、`zone_occupancy`、`persistence`。

- `server_instance_id`：服务实例标识，重启后变化。
- `snapshot_seq`、`sim_time`：读取时的世界状态序号和仿真秒数。
- `material_config_version`：物料参数版本。
- `material`：场景、物料版本、松落收敛状态、账本及库存，字段与 `/api/state` 的物料部分一致。
- `grid`：配置中的 `origin_x`、`origin_z`、`cell_size`、`cells_x`、`cells_z`，以及等长的 `coal_thickness_m`、`ground_elevation_m`、`zone_codes` 数组。

数组索引为 `z_index * cells_x + x_index`，`array_order=z-major`。单元中心为 `x=origin_x+(x_index+0.5)*cell_size`，`z=origin_z+(z_index+0.5)*cell_size`；`sample_location=cell_center`。地面、煤厚及位置单位为后端米；煤面高程为地面加煤厚。Unity 自行处理场景映射。

分类码 `0=outside`、`1=spill`、`2=yard`，附带 `zone_labels`。分类由配置区域决定且固定，不根据煤厚改变。散落库存是分类码为 1 的当前煤体积，不是历史累计量；松落或取回后重新反映当前库存。码为 0 的单元不接收煤料。

三组数组、物料版本和库存账本在同一个世界锁内读取并复制，返回对象的修改不影响仿真。默认网格为 1020×100 个单元；端到端实时性能仍待 Play 验收。

## 09 差量同步

`GET /api/material/update?server_instance_id=...&base_version=...` 返回 `base_version`、`new_version` 和 `changes`（等长数组 `indices`、`coal_thickness_m`），附带与该煤形同一快照的实例、序号、参数版本、物料账本、作业、区域占用、存档状态。地面及分类在重置之间固定，差量不重复携带完整网格。

后端记录每个单元最后修改版本，合并基线之后的修改为当前值；客户端跳过多个中间版本仍可衔接。版本没有变化时差量为空，状态仍可更新。旧实例、重置前或超前的基线返回 409 `MATERIAL_FULL_REQUIRED`，须读全量；重连也先读全量。重启后的版本基线从恢复版本重新建立，不复用旧实例。

Unity 在约 0.5 秒间隔读取，验证实例、序号、参数及差量基线，先完整校验再应用；旧响应不能覆盖新形状。网格和 `MaterialContext` 使用同一份响应，禁止将独立运动快照的账本拼接成煤形库存。失联保留最后有效表面；确认新实例未初始化则恢复原参考煤堆。

只替换 `StockyardRow_12` 下 `PlanYardCoal` 材质的参考煤 renderer；原对象、网格、材质保留，组件停用恢复。动态表面包含 yard/spill 有煤单元，每块最多 64×64 个间隔，变化只重建涉及的块。后端米映射为 1 Unity 单位，地面零点映射为 y=0.18；单元中心采样，外圈半单元不延展，图形网格不承担库存积分。其他场区和 21 台机器布局保留。

验证：`tests/test_material_sync.py` 3 项；Unity `YardCoalSyncTests` 4 项，覆盖完整/差量一致、跨版本及实例拒绝、无部分应用、场景映射及散落煤。现役场景结构与渲染另见 09 验收证据，Play 操作闭环属 10。
