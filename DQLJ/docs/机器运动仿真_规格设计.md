# 堆取料设备机器运动仿真规格 v0.1

日期：2026-09-30。状态：已实现后端与 Unity 运动闭环并完成自动及 Play Mode 联调；人工操作体验检查待完成。演示参数见《演示参数标定》，证据及验证边界见工作区 outputs/yard-machine-motion/验收记录.md。

## 1. 问题与目标

现有 Unity 场区有 21 台同类外形的堆取料设备，具备角色和行程范围标记，但没有堆取料机后端和运动联动。第一阶段建立后端权威运动状态、Unity 控制与展示闭环，为后续堆取料过程提供运动基础。

左侧 7 台为堆料角色，右侧 14 台为取料角色。角色不改变第一阶段基础运动能力。全部机器独立状态，开发先验证左右各一台，再扩展全部设备。

不模拟煤堆形变、吨位、切削、物料抛落、配煤、作业规划、碰撞保护、真实 PLC 或现场动力学；不增加手柄、网页三维界面和演示时间倍率。

## 2. 操作故事

1. 操作者能查看 21 台设备的编号、角色、连接、控制权与运动状态。
2. 操作者能选择设备，申请控制权并输入三轴目标。
3. 操作者能按住各轴正反向按钮运动，松开后减速停止。
4. 操作者能同时控制多个轴，单轴切换方式不影响其他轴。
5. 操作者能设置斗轮转速、皮带带速并独立启停。
6. 操作者能切换选机，并继续观察已启动设备的运行状态。
7. 操作者能普通停止、急停、解除急停和复位选中机器。
8. 观察客户端能看状态，但不能覆盖其他客户端的控制命令。
9. 操作者能看到拒绝命令的具体原因，例如无控制权、急停锁定、目标越界。
10. 操作者断线后设备停止，重新连接后不会自动恢复命令。
11. 服务重启后机器恢复配置初始姿态且全部停止。

## 3. 系统分工

DQLJ 为独立 Python/FastAPI 服务，建议默认 8001 端口，可配置。第一版单进程、单 worker、进程内状态，不持久化运行姿态。不得让多个 worker 分别维护同一组设备。

后端模块：设备配置与注册、运动内核、设备协调器、控制租约、固定步长时钟、API 和快照。Unity 模块：稳定设备身份、坐标映射、机械枢轴驱动、HTTP 协调器、选机与操作界面。

后端独立推进仿真，Unity 不发送推进时间命令，不计算权威速度、位置或限位。所有状态变更串行化；命令校验与应用为原子操作。现有装船机后端保持独立。可参考其 API/测试模式，但不复制匀速运动内核作为新运动算法。

## 4. 设备身份和配置

使用稳定 machine_id：左侧 ST01–ST07，右侧 RC01–RC14。绑定既有场景对象名称，不按运行时对象遍历顺序分配 ID。启动校验唯一性、数量、角色和场景映射版本。

后端配置包含：machine_id、role、配置版本、各轴初始位置、上下限、最大速度、加速度、减速度、到位容差、斗轮与皮带额定/最大速度及启停斜率。速度和加减速度必须为有限合法数值，初始姿态必须在限位内。

Unity 配置包含：机器 ID、场区父坐标系、轨道参考位置与方向、行走零点及场景单位/米比例、初始根姿态、各转动枢轴、角度零点与方向符号、几何比例及必要的臂长/连接点。轨道方向属于场区父坐标系，不因右侧机器初始朝向 180° 而反转。

启动不匹配时应明确报错并禁用对应机器命令，不静默按名称或默认比例继续。

## 5. 运动契约

### 5.1 三个定位轴

轴名 travel、slew、luff。位置单位分别为 m、deg、deg；速度为 m/s、deg/s，加速度为 m/s²、deg/s²。slew 为有限行程轴，不通过角度取模绕过限位。

模式：idle、target、jog、stopping；状态还包括实际带符号速度、目标（无目标时为 null）、正负限位及到位标记。

目标运动按速度与加减速度约束进行定位。制动距离 v²/(2d) 用于提前减速；必须处理剩余距离、换向和单步跨越停止时刻，不能仅靠事后截断位置。到位时速度归零并进入 idle。多轴可同时启动，但第一版不保证同时到达、不做路径规划。

jog 接管该轴并取消目标；若换向，先按减速度减至零，再向新方向加速。松开、失焦或 jog 续约超时进入 stopping。停止后进入 idle，原目标不恢复。

接近行程边界提前制动；边界处拒绝向外 jog、允许向内。越界目标返回错误，不静默裁剪。浮点末端误差可钳制在限位内，但正常运行不得依靠硬钳制实现制动。实际速度不得超过配置最大值。

### 5.2 斗轮和皮带

斗轮配置转速 rpm，快照给出转速及轮相位 deg；后端按 rpm×6 积分相位并取模。Unity 只对相位做跨 360° 的显示插值。皮带速度 m/s，快照给出累计运行距离，用于材质/带面运动，不表示煤量。

第一版速度设置为非负数，旋转/输送方向由配置确定，不提供运行中反转。启动时向设定速度加速，普通停止减速到零；设置 0 等价于停止。启动/改速不得超过配置上限。急停立即归零。

### 5.3 停止与复位

普通停止取消选中机器的所有目标和 jog，三轴、斗轮及皮带减速停止。急停立即归零、取消命令并锁定全部新运动命令。解除急停需要控制权，解除后仍保持停止。

复位停止并直接恢复初始姿态、轮相位、皮带运行距离，不播放回位动画。复位不得解除急停锁；需要继续操作时显式解除。停止时返回的快照与实际状态一致。

## 6. 控制权和连接保护

每个 Unity 运行会话使用新 client_id；每台机器同时有一份控制租约。获取成功返回不可猜测的 token 和递增 generation；写命令同时携带 client_id、token、generation。旧租约命令必须拒绝。第一版无账号鉴权，默认监听本机；控制 token 只用于控制竞争，不宣称为互联网安全机制。

客户端可以同时持有多个机器租约，切换选机不自动释放旧设备租约，以支持原设备的目标、斗轮和皮带继续运行。正在运行列表显示全部设备；客户端持续续约自己持有的全部租约。

建议初始协议参数（可配置，待实现时联调验证）：后端步长 0.02 s；整组快照 10 Hz；租约续约每 0.5 s，3 s 超时；jog 每 0.1 s 续约，0.35 s 超时。保护期限使用后端单调墙钟，与仿真时间分开。

切换选机先撤销旧机器全部 jog，再切换操作对象。按钮抬起/失焦立即发送停止 jog；Unity 自身未及时发送时，后端超时也必须停止 jog。target、斗轮、皮带在单纯失焦后继续，但连接租约必须由不依赖选机的协调器维护。

主动释放控制权或连接超时：取消该机器全部旧命令、按普通停止减速，进入 releasing 状态；完全停止后才允许新客户端获得控制权，避免新旧控制交叠。对客户端全部已控制机器逐台执行。拒绝在 releasing 期间重新开始运动。

重连只读最新快照，清空本地按键及待发送命令，不自动获取并恢复旧命令。若旧租约尚有效可确认其状态；已过期则显式重新获取新租约。急停状态在连接变化后仍保留。

命令携带 command_id 和递增 command_seq；同一租约内拒绝过期顺序，同 ID 同载荷重试返回既有结果，同 ID 不同载荷报错。jog 还携带每轴递增序号，延迟续约不能重新启动已松开的运动。过期或乱序请求不刷新有效保护期限。

## 7. HTTP 接口与快照

| 方法与资源 | 用途 |
| --- | --- |
| GET /health | 进程健康与服务实例 ID |
| GET /api/machines | 21 台身份、角色与配置概要 |
| GET /api/state | 全部机器、sim_time、快照序号、配置版本 |
| POST /api/machines/{id}/control/acquire | 申请控制权 |
| PUT /api/machines/{id}/control/heartbeat | 续约 |
| DELETE /api/machines/{id}/control | 释放并停止 |
| POST /api/machines/{id}/commands | 提交类型化运动命令 |

命令类型：set_targets（可含一至三轴，原子校验）、jog（方向 ±1 和速度）、stop_jog（指定轴或全部 jog）、set_wheel、set_belt、stop、estop、clear_estop、reset。未知轴、设备、非有限数值、非法速度及参数组合必须拒绝，无部分应用。

每台快照包含 machine_id、role、axes、wheel、belt、estop_latched、control（公开 owner_id、generation、状态及剩余租约，不包含 token）、running、last_command_id 和结构化拒绝/停止原因。running 按实际运动和活动命令计算，不按选中对象计算。

命令响应包含 command_id、accepted、snapshot_seq 与该机器快照。统一错误结构 code/message/context：404 UNKNOWN_MACHINE；422 INVALID_COMMAND/OUT_OF_RANGE；409 CONTROL_HELD/CONTROL_RELEASING/ESTOP_LATCHED/STALE_COMMAND；403 CONTROL_REQUIRED。Unity 显示可理解的中文原因。

快照增加 server_instance_id，服务重启即改变；Unity 清空旧插值缓存、租约与命令序号。相同实例内仅接受递增快照序号，避免异步轮询覆盖更新结果。

## 8. Unity 映射与模型修正

行走移动整个机器根节点，而非只移动底架。映射采用场区父坐标系轨道向量：初始位置加轨道方向乘行走相对零点距离及场景比例。初始化映射必须精确还原既有摆位。

回转驱动上部结构绕竖直枢轴。俯仰必须把臂架、斗轮和对应子结构建立在真实的演示铰点下；重设枢轴时保留初始几何位置。吊索和连接件根据连接点更新，不能悬空或随错误父节点运动。斗轮绕轮中心局部轮轴旋转。后供料臂第一版无独立运动轴，保持现有结构关系。

统一从后端角度映射到 Unity 初始姿态和方向符号，不把 Unity Euler 角直接回传作为运动真值。显示可采用约一快照周期的有界插值；不在失联时无限外推。急停/复位收到后立即应用快照并清空插值历史。

模型实例 0.455 几何缩放不能自动推导出轨道场景单位/米比例。第一版可选 1 场景单位/米作为明确的演示映射默认值，但必须标记 demo 并核对父级变换；最终由配置生成流程校验。不得称为现场比例。

Unity 界面包含角色分组选机、控制权获取/释放、三轴目标和 jog、斗轮/皮带速度及启停、停止/急停/解除/复位、连接状态、拒绝原因和正在运行设备列表。无控制权时禁用写操作。选机或断线清空局部按钮按住状态。

同步更新生成器、prefab 与 Demo/VideoPreview 两份场景的绑定，保持初始布局和角色，生成工具重复执行不产生重复组件。不得通过重建整个港区来安装控制器。

## 9. 参数标定表与尚待实证项

行走范围和初始摆位以两份当前场景中角色组件与根姿态核对结果为准，生成器为交叉依据。不能仅用生成器默认值覆盖已有手工场景差异。

三轴速度、加减速度、回转/俯仰上下限、轮速、带速和方向，尚无这些设备的实机依据。实现前形成版本化参数表：字段、单位、值、来源、demo 标记及校验结果。俯仰范围须用修正后的枢轴验证可展示姿态；本期不把验证称为碰撞保护。

后端不在启动时依赖 Unity 在线。设备及标定配置作为版本化交付物；Unity 和后端校验兼容版本。不得从论文案例机械尺寸直接填入当前模型作为已确认参数。

## 10. 验证方案

以公开命令与状态快照为主要行为测试接口，使用可控时钟验证运动及超时，不依赖真实 sleep。补充 Unity 的枢轴与绑定测试，以及实际 Play Mode 联通验收。

后端必须覆盖：加速/减速与速度上限、短距离到位、换向、限位制动、三轴并行、jog 接管及续约超时、延迟请求不复活、普通停止、急停锁/解除/复位、控制冲突、释放期间拒绝接管、多个持有机器断线停止、21 台状态隔离、服务重启初始化。

API 测试覆盖：非法及非有限参数原子拒绝、token/generation 校验、乱序与幂等、全组快照序号和服务实例变化。命令失败不能改变其他轴或机器。

Unity 自动检查：21 台 ID 唯一且角色 7/14、枢轴与映射存在、初始姿态不变、根节点行走、轮轴旋转、两份场景映射一致、重复安装无重复。

Play Mode 验收：左右各一台验证目标/jog/换向/三轴联动与斗轮皮带；切换机器时停止 jog 而保留其他运动；全部 21 台可选择；两客户端冲突；失焦、断线与重连；急停立即展示；重启回初始姿态。记录命令、后端快照和 Unity 姿态误差，而非仅凭肉眼宣称一致。

默认计算容差建议：行走 0.001 m、角度 0.01 deg。Unity 插值稳态误差在映射后的到位容差内；动态显示允许约一快照周期延迟。这些是软件验收建议，不是实机测量精度。
