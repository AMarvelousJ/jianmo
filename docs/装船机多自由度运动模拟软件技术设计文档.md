# 装船机多自由度运动模拟软件技术设计文档

**文档版本：** v0.1
**对应 PRD：**《装船机多自由度运动模拟软件 PRD》v2.0
**技术路线：** Python
**当前阶段：** 技术设计草案
**核心目标：** 实现装船机多自由度运动仿真内核，并提供可视化验证与状态输出能力。

---

## 1. 设计背景

本项目当前目标不是优先实现 PLC 联调、工艺编排或完整标签系统，而是优先实现“装船机机构建模 + 多运动轴匀速运动 + 正运动学位姿计算 + 实时仿真状态输出”的程序内核。PRD 中已明确，第一阶段应形成一个可被 HMI、PLC API、后续工艺规划模块共同复用的运动仿真内核。

因此，本技术设计文档的重点不是界面功能堆叠，而是把装船机的每一个自由度、每一次时间推进、每一个关键点坐标计算，都设计成可编码、可测试、可扩展的结构。

---

## 2. 已确认设计边界

根据人工确认结果，本阶段采用以下边界：

| 编号 | 项目      | 当前确认结果                           |
| -- | ------- | -------------------------------- |

| 3  | 技术栈     | Python                           |

|    |         |                                  |

## 3. MVP 技术范围

本阶段只实现单台装船机的多自由度运动模拟。MVP 范围包括装船机机构模型、多自由度运动轴、皮带运行状态、匀速运动模型、正运动学、船舶横滚/俯仰背景、状态输出、API 预留和基础可视化验证。

### 3.1 本阶段包含

1. 单台装船机实例。
2. 行走、回转、臂架俯仰、臂架伸缩、溜筒旋转五个运动自由度。
3. 皮带运行状态模拟。
4. 固定时间步仿真循环。
5. 每个运动轴的匀速逼近目标值。
6. 根据轴值计算装船机关键点坐标。
7. 输出完整状态快照。
8. 提供基础命令接口和状态读取接口。
9. 提供 3D 可视化验证，必要时降级为 2.5D。

### 3.2 本阶段不包含

1. 真实 Allen-Bradley PLC 通讯。
2. 完整 PLC 标签系统。
3. 多台装船机协同。
4. 作业工艺流程。
5. 自动装舱一轮、二轮策略。
6. 真实碰撞检测。
7. 复杂动力学、惯性、液压、电机动态。
8. 加速度、减速度曲线。
9. 煤流、堵料、跑偏、重量、船舱容量。

## 4. 总体架构设计

系统采用“运动内核与可视化解耦”的结构。运动内核只负责计算，不依赖任何界面；可视化层只消费状态快照，不反向参与运动计算。

```text
┌─────────────────────────────────────┐
│           Visualization Layer        │
│     3D Viewer / 2.5D Viewer           │
└──────────────────▲──────────────────┘
                   │ consume state snapshot
┌──────────────────┴──────────────────┐
│              API Layer               │
│ MotionCommandApi / SimulationStateApi │
└──────────────────▲──────────────────┘
                   │
┌──────────────────┴──────────────────┐
│          SimulationWorld             │
│  time loop / object manager / state   │
└──────────────────▲──────────────────┘
                   │
┌──────────────────┴──────────────────┐
│             ShipLoader               │
│ geometry / axes / kinematics / belt   │
└───────▲──────────────▲───────────────┘
        │              │
┌───────┴───────┐  ┌───┴────────────────┐
│  MotionAxis   │  │  KinematicsSolver   │
└───────────────┘  └────────────────────┘
```

这个分层与 PRD 中建议的架构一致：上层是 Application / Demo / HMI，中间是命令 API 与状态 API，底层是 SimulationWorld、ShipLoader Motion Kernel、MotionAxis、KinematicsSolver、VesselMotion 等模块。

## 5. 模块划分

### 5.1 `SimulationWorld`

职责：

1. 管理仿真时间。
2. 按固定时间步推进系统。
3. 管理装船机对象。
4. 管理船舶背景运动对象。
5. 输出统一状态快照。
6. 支持暂停、恢复、单步、重置。

核心字段：

```python
class SimulationWorld:
    sim_time: float
    dt: float
    running: bool
    ship_loader: ShipLoader
    vessel_motion: VesselMotion
```

核心方法：

```python
step(dt: float) -> SimulationSnapshot
pause() -> None
resume() -> None
reset(initial_state: dict) -> None
get_snapshot() -> SimulationSnapshot
```

---

### 5.2 `ShipLoader`

职责：

1. 聚合装船机几何参数。
2. 管理所有运动轴。
3. 管理皮带状态。
4. 调用正运动学求解器。
5. 生成装船机状态。

核心字段：

```python
class ShipLoader:
    loader_id: str
    geometry: ShipLoaderGeometry
    axes: dict[str, MotionAxis]
    belt_state: BeltState
    kinematics_solver: KinematicsSolver
```

核心方法：

```python
update(dt: float) -> None
set_axis_target(axis_id: str, target: float, velocity: float) -> None
start_axis(axis_id: str) -> None
stop_axis(axis_id: str) -> None
set_belt(speed: float, running: bool) -> None
compute_state() -> ShipLoaderState
```

---

### 5.3 `MotionAxis`

`MotionAxis` 是本系统最核心的底层对象之一。所有运动轴都采用统一模型，后续才能方便加入限位、加速度、碰撞约束和联锁逻辑。

PRD 已经定义每个运动轴应包含轴标识、轴类型、当前值、目标值、速度、使能状态、运行状态、到位状态、正方向、最小值、最大值、到位容差、更新时间和约束结果等字段。

核心字段：

```python
class MotionAxis:
    axis_id: str
    axis_type: str  # linear / rotary
    current_value: float
    target_value: float
    velocity: float
    enabled: bool
    running: bool
    at_target: bool
    min_value: float | None
    max_value: float | None
    tolerance: float
    wrap_angle: bool
    shortest_path: bool
```

更新规则：

```python
def update(self, dt: float):
    if not self.enabled or not self.running:
        return

    distance = self.target_value - self.current_value
    max_step = self.velocity * dt

    if abs(distance) <= self.tolerance:
        self.current_value = self.target_value
        self.running = False
        self.at_target = True
        return

    if abs(distance) <= max_step:
        self.current_value = self.target_value
        self.running = False
        self.at_target = True
    else:
        self.current_value += sign(distance) * max_step
        self.running = True
        self.at_target = False
```

该规则对应 PRD 中的匀速运动更新逻辑：每个仿真周期根据目标差值、速度和时间步计算最大步长，并保证轴值不会越过目标值。

---

### 5.4 `KinematicsSolver`

职责：

1. 把运动轴数值转化为真实机构姿态。
2. 计算基座、臂架根部、臂架端部、溜筒顶部、溜筒底部、落料点。
3. 输出方向向量和姿态信息。
4. 不管理时间，不管理命令，不管理可视化。

PRD 已经明确，系统必须把“轴值”转化为“真实机构姿态”，不能只停留在数值变化。每个周期至少要输出基座、臂架、溜筒、落料点等关键坐标。

核心方法：

```python
class KinematicsSolver:
    def solve(
        self,
        geometry: ShipLoaderGeometry,
        axis_values: dict[str, float]
    ) -> KinematicsResult:
        ...
```

输出结果：

```python
class KinematicsResult:
    base_position: Vec3
    boom_root_position: Vec3
    boom_tip_position: Vec3
    chute_top_position: Vec3
    chute_bottom_position: Vec3
    discharge_point: Vec3
    boom_direction: Vec3
    chute_direction: Vec3
    loader_pose: Pose
    boom_pose: Pose
    chute_pose: Pose
```

---

### 5.5 `VesselMotion`

职责：

1. 生成船舶横滚角。
2. 生成船舶俯仰角。
3. 作为背景显示输入。
4. 不参与装船机落料点坐标计算。

核心字段：

```python
class VesselMotion:
    roll_deg: float
    pitch_deg: float
    roll_amplitude_deg: float
    pitch_amplitude_deg: float
    roll_period_s: float
    pitch_period_s: float
    enabled_periodic_motion: bool
```

核心方法：

```python
update(sim_time: float) -> None
get_pose() -> VesselPose
```

第一版中，`VesselMotion` 只输出背景姿态，不改变 `discharge_point` 的世界坐标，也不计算落料点在船体坐标系下的位置。

## 6. 坐标系设计

### 6.1 世界坐标系 `World`

采用右手坐标系：

| 轴 | 含义         |
| - | ---------- |
| X | 沿码头 / 船长方向 |
| Y | 从码头指向船舶方向  |
| Z | 竖直向上       |

该定义与 PRD 中建议的世界坐标系一致：X 沿码头/船长方向，Y 从码头指向船舶方向，Z 竖直向上。

---

### 6.2 装船机基座坐标系 `LoaderBase`

原点建议放在装船机回转中心投影点或回转中心位置。

本设计中采用：

```text
LoaderBase 原点 = 回转中心世界坐标
```

行走轴改变 `LoaderBase` 在 `World` 中的位置。

---

### 6.3 回转坐标系 `SlewFrame`

`SlewFrame` 随回转角绕世界 Z 轴旋转。

```text
slew = 0° 时，臂架默认朝 +Y 方向伸出
slew > 0° 时，按右手系绕 Z 轴旋转
```

---

### 6.4 臂架坐标系 `BoomFrame`

臂架根部位于 `boom_root_position`。

臂架方向由两个角共同决定：

1. 回转角 `slew`
2. 俯仰角 `boom_luff`

臂架长度：

```text
boom_total_length = boom_base_length_m + boom_extension
```

---

### 6.5 溜筒坐标系 `ChuteFrame`

第一版简化处理：

1. 溜筒顶部位置等于臂架端部位置。
2. 溜筒主体默认沿竖直方向向下。
3. 溜筒旋转只绕竖直轴旋转。
4. 因为绕竖直轴旋转不会改变竖直溜筒底部位置，所以第一版中 `chute_rotate` 主要影响 `chute_direction` 或 `discharge_direction`，不改变 `chute_bottom_position` 的 XY 位置。

---

### 8.1 自由度说明

| 自由度              | 类型   | 单位         | 第一版处理          |
| ---------------- | ---- | ---------- | -------------- |
| `travel`         | 平移轴  | m          | 沿轨道方向匀速移动      |

## 9. 正运动学计算设计

### 9.1 输入

```python
axis_values = {
    "travel": 10.0,
    "slew": 30.0,
    "boom_luff": 12.0,
    "boom_extension": 5.0,
    "chute_rotate": 20.0
}
```

### 9.2 计算流程

PRD 建议正运动学采用矩阵或向量变换链，而不是手工拼凑零散坐标。整体变换链为：世界坐标系 → 行走平移 → 基座高度/偏移 → 回转 → 臂架根部偏移 → 俯仰 → 臂架长度/伸缩 → 溜筒旋转 → 溜筒长度 → 落料点。

本设计采用向量 + 旋转矩阵实现。

---

### 9.3 基座位置计算

```text
base_position =
    rail_origin
    + rail_direction * travel
    + [0, 0, base_height_m]
```

---

### 9.4 臂架根部计算

```text
boom_root_position =
    base_position
    + rotate_z(slew) * boom_base_offset
```

---

### 9.5 臂架方向计算

假设 `slew = 0°` 时臂架朝 +Y 方向。

水平朝向：

```text
horizontal_direction = rotate_z(slew) * [0, 1, 0]
```

俯仰角影响：

```text
boom_direction.x = horizontal_direction.x * cos(luff)
boom_direction.y = horizontal_direction.y * cos(luff)
boom_direction.z = sin(luff)
```

---

### 9.6 臂架端点计算

```text
boom_total_length = boom_base_length_m + boom_extension

boom_tip_position =
    boom_root_position
    + boom_direction * boom_total_length
```

---

### 9.7 溜筒顶部计算

```text
chute_top_position = boom_tip_position
```

---

### 9.8 溜筒底部计算

第一版溜筒默认竖直向下：

```text
chute_bottom_position =
    chute_top_position
    + [0, 0, -chute_length_m]
```

---

### 9.9 溜筒方向计算

由于人工确认“溜筒只绕竖直轴旋转”，第一版将 `chute_rotate` 解释为落料方向或溜筒朝向标识，而不是复杂摆动。

```text
chute_direction =
    rotate_z(slew + chute_rotate) * [0, 1, 0]
```

注意：

```text
chute_rotate 不改变 chute_bottom_position
chute_rotate 只改变 chute_direction / discharge_direction
```

---

### 9.10 落料点计算

```text
discharge_point =
    chute_bottom_position
    + discharge_offset
```

默认：

```text
discharge_offset = [0, 0, -0.5]
```

第一版中，落料点位置主要受以下自由度影响：

1. 行走 `travel`
2. 回转 `slew`
3. 臂架俯仰 `boom_luff`
4. 臂架伸缩 `boom_extension`

第一版中，溜筒旋转 `chute_rotate` 只影响方向表达，不影响落料点空间坐标。

## 11. 命令 API 设计

第一版不实现真实 PLC 通讯，只提供命令输入和状态读取边界。PRD 中也明确：PLC 侧在本阶段仅作为外部系统边界，只预留 API 接口，不能让 PLC 标签变化反过来主导运动仿真模型设计。

### 11.1 Python 内部接口

```python
world.command_api.set_axis_target("travel", target=20.0, velocity=1.0)
world.command_api.start_axis("travel")

world.command_api.set_axis_target("slew", target=45.0, velocity=5.0)
world.command_api.start_axis("slew")

```

## 12. 可视化设计

### 12.1 首选方案：Python 3D 可视化

推荐优先尝试：

```text
PyVista / VTK
```

1. Python 生态内可快速绘制 3D 点、线、管状结构。
2. 适合验证空间坐标和运动轨迹。
3. 对 MVP 来说，比 Unity、Unreal 成本低。
4. 可直接消费 Python 内核输出的状态快照。

### 12.2 3D 显示对象

如果 3D 实现耗时过高，降级为：

1. 俯视图：显示 X-Y 平面上的行走、回转、伸缩、落料点。
2. 侧视图：显示 Y-Z 或 X-Z 平面上的俯仰、高度、溜筒和落料点。
3. 状态面板：显示各轴当前值、目标值、速度、运行状态。

2.5D 的优势是开发简单，验收逻辑清楚。缺点是空间真实感弱于 3D。

## 17. 单元测试设计

PRD 的非功能需求中明确要求系统具备可测试性，运动轴和正运动学应能做单元测试，并且有明确输入输出。

### 17.1 `MotionAxis` 测试

测试点：

1. 轴能按速度逼近目标。
2. 轴不会越过目标。
3. 到达目标后 `running = False`。
4. 到达目标后 `at_target = True`。
5. 暂停或禁用时轴值不变化。
6. 速度为 0 时不应异常。

示例：

```python
def test_axis_reaches_target_without_overshoot():
    axis = MotionAxis(
        axis_id="travel",
        axis_type="linear",
        current_value=0.0,
        target_value=1.0,
        velocity=0.6,
        running=True,
        enabled=True,
        tolerance=0.01
    )

    axis.update(1.0)
    assert axis.current_value == 0.6

    axis.update(1.0)
    assert axis.current_value == 1.0
    assert axis.at_target is True
    assert axis.running is False
```

---

### 17.2 `KinematicsSolver` 测试

测试点：

1. 行走变化应改变所有关键点世界坐标。
2. 回转变化应改变臂架端部 XY 坐标。
3. 俯仰变化应改变臂架端部 Z 坐标。
4. 伸缩变化应改变臂架端点距离。
5. 溜筒底部应始终跟随臂架端点。
6. 溜筒旋转只改变方向，不改变溜筒底部位置。

---

### 17.3 `SimulationWorld` 测试

测试点：

1. 单步推进后 `sim_time += dt`。
2. 暂停后 `sim_time` 不变化。
3. 多轴可同时更新。
4. 状态快照时间与轴状态一致。
5. 重置后状态恢复初始值。

## 20. 风险与处理策略

### 20.1 真实几何参数缺失

风险：

运动效果可能不够贴近真实装船机。

处理：

第一版全部参数配置化，使用工程默认值。后续获取真实参数后，只替换配置文件，不重写代码。

---

### 20.2 3D 可视化实现成本偏高

风险：

3D 视图可能消耗过多时间，影响运动内核开发。

处理：

先保证运动内核和状态快照正确。3D 失败时，立即降级为 2.5D：俯视图 + 侧视图。

---

### 20.3 溜筒旋转定义过于简化

风险：

真实装船机溜筒可能不只是绕竖直轴旋转，后续如果要模拟摆动或伸缩，需要扩展。

处理：

第一版只改变 `chute_direction`。后续如需要真实溜筒摆动，可新增：

```text
chute_swing_x
chute_swing_y
chute_extension
```

不要直接修改现有 `chute_rotate` 的语义。

---

### 20.4 船舶运动暂不参与落料坐标

风险：

后续如果要判断落料点是否在船舱内，需要额外计算世界坐标到船体坐标的转换。

处理：

第一版状态中保留：

```json
"used_for_discharge_coordinate": false
```

后续版本增加：

```text
world_to_vessel_transform
discharge_point_in_vessel
```

---

### 20.5 可视化与内核耦合

风险：

如果可视化直接参与计算，后续接 PLC/HMI 会困难。

处理：

可视化只能读取 `SimulationSnapshot`，不能直接修改 `ShipLoader` 内部状态。

---

## 21. 当前技术结论

本项目下一步不应继续扩写 PRD，而应基于当前 PRD 和已确认边界，进入技术实现准备阶段。

第一版技术路线为：

```text
Python
+ 工程默认参数
+ MotionAxis 匀速运动模型
+ KinematicsSolver 正运动学
+ SimulationWorld 固定时间步
+ SimulationSnapshot 状态快照
+ PyVista 3D 可视化优先
+ 2.5D 兜底
+ API 边界预留
```

最关键的开发判断是：

```text
先把运动内核做对，再做界面和外部接口。
```

如果 `MotionAxis` 和 `KinematicsSolver` 不稳定，后面的 HMI、PLC、工艺规划都会建立在错误基础上。因此第一阶段必须优先保证：

1. 轴值更新正确。
2. 多轴同步正确。
3. 正运动学关键点正确。
4. 状态快照稳定。
5. 可视化只用于验证，不参与计算。
