# 物料存档与恢复

08 保存物料状态及目标进度，不保存机器运动或控制凭据。默认后端启用存档，位置为 `DQLJ/data/material-snapshot.json`，可用环境变量 `DQLJ_SNAPSHOT_PATH` 指定另一个路径。路径为空时仍使用默认路径。文件由单进程单 worker 管理，不支持多个服务共享同一文件。数据目录不入 Git。

独立构造 `World()` 默认不持久化；测试或工具以 `World(snapshot_path=...)` 显式启用。无存档且无备份时从未初始化状态启动。已有无效文件时禁止静默初始化覆盖。

## 保存

1× 仿真每约 1 秒保存；开始、暂停、恢复、终止、显式收尾、停止/急停/驱动停止、控制释放/超时、机器及物料复位等命令也触发保存。正常服务退出再保存一次。周期由仿真时间驱动；磁盘故障不保证最近一周期内的数据可恢复，失败状态会明确显示。

存档包括格式版本、UTC 保存时间、完整机器/几何/物料配置、仿真时间与序号、物料版本、地面和煤厚、初始/输入/输出账本、待处理松落队列、作业记录及目标累计量。区域分类从同一配置重建，库存从煤厚重算。机器姿态、轮带运行、租约令牌及命令缓存不保存。

同一世界锁内复制数据，用规范 JSON 计算 SHA-256。临时文件写完、flush 和 fsync 后原子替换；`.bak` 保存上一份已验证有效的完整版本。认证物料重置只保存一次，备份保持重置前的完整物料版本。未完成临时文件不会作为恢复来源。

`/api/state.persistence` 提供 `enabled`、`interval_s`、`last_saved_at_utc`、`last_saved_snapshot_seq`、`last_saved_material_version`、`error`、`recovery_required`、`loaded_from`、`recovery_warning`。保存失败不会更新成功时间；命令接受表示内存操作接受，不代表保存成功，界面须同时检查该状态。

## 恢复

先验证格式、校验值、完整配置兼容性，再检查网格尺寸/数值/硬边界、地面配置、账本守恒、松落队列、作业目标和进度。配置全文比对，版本字符串相同但参数不同也拒绝盲目加载。

所有作业记录转为 `stopped`，原状态保存在 `saved_status`。原未结束作业可在获取新控制权、发送 `resume_job` 并重新申请区域后续作；原 completed/terminated/incomplete 记录仅供历史查看，不能恢复。目标和实际累计保持，轮带转速与物料流量为零，机器使用原运动阶段的初始姿态，区域及控制租约清空，服务实例标识更新。

后台仍可处理已保存的松落队列，煤形可能继续趋于稳定；这不会产生新的物料输入或输出。显式恢复还需操作设备姿态及轮带，不能把恢复进度等同于恢复机器运动。

原有 running/paused 作业需先结束才能重置；重启恢复的 stopped 作业允许在双设备控制权、停稳和确认后重置，旧进度转 terminated，建立新煤形/初始库存并清零输入输出，物料版本递增且立即保存。

## 故障与边界

主档损坏会保留原文件及 `.rejected-...` 证据，验证有效备份后回退，状态显示来源和警告。无法保存证据或两份文件均无效/不兼容时，保持未初始化、停止状态并设置 `recovery_required=true`，拒绝初始化、开始、恢复和物料重置，保留文件供人工检查。修复有效存档及配置后重启；没有自动清档入口。

正常周期写入成功时，异常进程退出最多丢失最近未保存周期；该结论不承诺硬件断电、磁盘损坏或存档持续失败下的数据完整性。

当前保存同步持有世界锁。独立演示采样 10 次：文件约 872 KB，平均 33.59 ms、最大 34.27 ms。可能短暂延迟控制处理，尚未验收 HTTP/Unity 端到端实时性能。后续需依据联通表现决定是否改为有界异步写入。
